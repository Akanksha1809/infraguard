# Sample outputs

Real, committed output from running InfraGuard against the committed example inputs —
generated by actually running these commands (not hand-written), so a reviewer can read
expected results without installing or running anything:

```bash
infraguard analyze-change --plan examples/terraform/sample/plan.json
    # -> change_analysis/report.{json,md}

infraguard simulate-failure \
    --topology examples/topologies/redundant-app-shared-db-bottleneck.yaml --failure db
    # -> failure_simulation/report.{json,md}

infraguard assess-recovery --policy examples/recovery/policy.yaml \
    --evidence examples/recovery/evidence.json --as-of 2026-10-19T12:00:00Z
    # -> disaster_recovery/report.{json,md}
```

Each `run_id` embedded inside the JSON/Markdown will differ if you regenerate these
yourself (it's a fresh UUID per run) — everything else (findings, severities, the readiness
verdicts) is deterministic given these fixed inputs and, for the recovery assessment, a
fixed `--as-of`.
