# Example Terraform config for `infraguard analyze-change`

`main.tf` here uses only the `local` and `random` providers — no cloud account, credentials,
or cost. `plan.json` in this directory was generated by actually running the documented
workflow against this exact config (not hand-written):

```bash
cd examples/terraform/sample
terraform init
terraform plan -out=tfplan
terraform show -json tfplan > plan.json
```

Then, from the repository root:

```bash
uv run infraguard analyze-change --plan examples/terraform/sample/plan.json
```

This plan is all-`create` (a fresh config, never applied), so it is a clean baseline: the
default policy returns a `warn` decision (exit code 0) because every resource has
attributes that are only known after apply (file hashes, generated IDs) — a true and
expected finding, not a flaw in the example. For destructive/replace/sensitive-value
scenarios, see the hand-crafted fixtures under `tests/fixtures/change_analysis/`, which
exist specifically to exercise those paths deterministically.

Regenerate `plan.json` yourself any time by re-running the three commands above; `.terraform/`
and `tfplan` are gitignored since they're local build artifacts, not source.
